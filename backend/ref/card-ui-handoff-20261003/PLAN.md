## 실행 순서와 통과 기준

1. 설치한 V6 차트 요약 CSS를 독립 사후 검토하고 정상 커밋한다. 공개 원본 실패와 수정안 결과, 실제 글자 경계·최종 열·새 화면 이미지를 비교한다. 같은 숫자·단위·부호·0값과 기관 상세 동작을 보존한다.
2. 승인된 소스로 실제 앱을 정상 재실행한다. 최소 질문 `삼성전자 최근 3개월 차트`를 한 번 제출하고 최대2560×1392→같은 카드 축소1411×1166→재최대화, 하단·마지막 열·탭·펼침을 확인한다. 목표 크기와 실제 측정 크기가 다르면 실제 크기를 기록한다.
3. 질문지의12개 seed와31개 추가 흐름을 따라 범위 내94개 상태를 순회한다. 새 호출과 기존 결과 재관측을 구분한다. 전체 최신 통과는 상태별 같은 카드 창 순환 증거가 갖춰졌을 때만 집계한다.
4. 발견한 공백·잘림·라벨·단위·출처·빈 상태 결함을 최소 수정한다. 작성자와 별도 검토자의 검증을 분리하고 실제 앱에서 실패한 입력·조작을 다시 실행한다. 없는 데이터를 만들어 공백을 채우지 않는다.
5. 수정 결과를 Paper의 별도 편집 가능한 개선 도면과 최소 입력 질문지에 반영한다. 원본101개, 과거 실패와 정정 기록은 보존한다. 실제 금융값·사적 화면은 공개 문서와 Paper에 옮기지 않는다.
6. 전체 요구사항을 독립 최종 검토하고 변경에 맞는 필수 테스트를 실행한다. 기본diff 검사와 `npm --prefix app run test:unit` 등 프로젝트 필수 검사를 통과시킨다. 실행 불가능한 검사나 잔여 실패는 통과로 표시하지 않는다.
7. `powershell -File scripts/security/eval-security-gates.ps1`의 `ALL_GATES_PASS`와 최종 검토를 확인한 뒤 허용된 UI 브랜치를 정상push한다. 기본 훅을 유지하고 `--no-verify`, 강제push, 누출을 숨기는 이력 변경을 사용하지 않는다.

## 증거 기록

각 상태에 최소 입력 또는 탭·펼침 조작, 호출 성공/실패, UI 판정과 범위, 실제 창 크기·배율, 스크롤·최종 열·하단, 관측 시각, 런타임 소스, 원본 이미지 경로를 기록한다. 화면에서 실제template ID를 확인하지 못하면null을 유지하고 예상 참조와 구분한다.

카드가 생성되지 않은 호출은 UI NOT_RUN으로 기록한다. 부분 통과·합성 검증·소스 승인·2122px 일반 창을 전체94개 실제 최대 창 통과로 확대하지 않는다. 모의 탐색 결과의 정확성이나 분석·추가 질의의 연결 성공도 별도 증거 없이 추정하지 않는다.

## GitHub 인계 시점 — 2026-10-03

사용자가 다른 컴퓨터로 이동하도록 GitHub 업로드를 요청했고, 업로드 후 이 컴퓨터의 목표 일시정지를 명시했다. UI 인계 브랜치는 `codex/card-ui-resume-20261003`이다. LAYA는 `codex/laya-experiments-20261001` 별도 브랜치로 보존한다. main 병합이나 전체 목표 완료를 의미하지 않는다.
