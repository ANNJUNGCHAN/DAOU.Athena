# 카드 UI 작업 재개

**최신 재개 결과:** [CURRENT-RESUME-20261003.md](CURRENT-RESUME-20261003.md)를 먼저 읽는다. 2026-10-03 재개에서 단위 검사 800개를 통과하고 날짜축·기업정보 간격·REST 상태 카드 후보를 적용했다. 실제 앱 94개 상태 전체 검증과 Paper 원본 개수 재확인은 아직 남아 있다. 독립 검토는 [새 검토 기록](reviews/RESUME-20261003-INDEPENDENT.md)에 있다.

아래 적용 상태·실패 수·미적용 후보 설명과 `STATE.json`의 소스 핀은 최초 인계 커밋 `1c0e7e7` 시점의 기록이다. 새 결과와 구분해 보존하며, 현재 소스의 승인 범위와 남은 순서는 최신 재개 기록을 따른다.

이 브랜치는 완료된 UI 배포본이 아니라 다른 컴퓨터에서 이어갈 작업과 검증 자료다. 원래 목표인 Paper 101개 편집 가능한 상태 보존, 실제 앱의 94개 상태 검증은 유지한다. 실거래·실제 주문 7개 상태는 제외하며 백테스트의 모의 거래는 포함한다.

제품 변경의 기본 공백 검사는 통과했지만, 해시를 보존해 옮긴 과거 snapshot·archive에는 CR 줄 끝과 기존 끝 공백이 있어 인계 전체의 기본 `git diff --check`는 실패했다. 검증 자료의 원본 바이트를 일괄 수정하지 않았다. 전체 단위 검사도 아래와 같이 실패 상태이므로 이 브랜치를 검증 완료 배포본으로 병합하지 않는다.

## 다른 컴퓨터에서 시작

```powershell
git clone --branch codex/card-ui-resume-20261003 https://github.com/ANNJUNGCHAN/DAOU.Athena.git
cd DAOU.Athena
node backend/ref/card-ui-handoff-20261003/resume.mjs
```

이미 저장소가 있으면 기존 변경을 먼저 보존하고 다음을 실행한다. 로컬 변경을 reset하거나 강제로 덮어쓰지 않는다.

```powershell
git fetch origin
git switch codex/card-ui-resume-20261003
git pull --ff-only
node backend/ref/card-ui-handoff-20261003/resume.mjs
```

그다음 Codex에서 이 폴더를 열고 **“카드 UI 계획 이어서 실행해”**라고 지시한다. `AGENTS.md`가 이 문서와 계획서를 연결한다. `resume.mjs`는 ignored `.omc/plans`에 계획을 복원하고 재개 프롬프트를 출력한다. 기존 로컬 계획은 덮어쓰지 않는다. Git pull이나 이 스크립트만으로 Codex 작업 또는 앱을 자동 시작하지 않는다.

Node.js와 npm, 앱 의존성 및 필요한 백엔드 환경은 새 컴퓨터에서 준비한다. `npm --prefix app ci`와 저장소 README의 설치·실행 절차를 따른다. 인증은 새 컴퓨터의 앱에서 직접 설정한다. 현재 컴퓨터의 `.env`, 인증 정보, 실제 대화 DB, 사용자 프로필은 인계하지 않는다.

## 적용 상태

- 계좌 조회 조건 보완과 늦은 응답 억제: 제품 소비자 18개 검사 및 독립 설치 검토를 거쳤다.
- 기업정보 가격·PER/PBR 단위 3파일: 제품 소비자 338개 검사와 독립 검토를 거쳐 적용했다. 실제 관측 978–982는 지정 단위·배치 범위의 증거다.
- 차트 복귀·재마운트 및 계좌 합성 4파일: 독립 사전·설치 후 검토를 거쳐 적용했다. 현재 소스의 실제 새 차트 호출은 시간 초과했으므로 실제 앱의 전환 성공은 미검증이다.
- 계좌 부분 미제공 안내 및 가로 이동 안내: 소스에 적용했다. 실제 설치 소스 소비자 64개 및 추가 20개 검사를 통과했다. 새로 추가한 7줄의 CR만 정리한 후 기본 공백 검사도 통과했다. 적용 후 실제 앱 검증은 아직 하지 않았다.
- 공개 질문지는 기존 관측 977까지 적용되어 있다. 추가 978–996 부록의 최신 상태는 `verification/questionnaire/`의 보고서를 확인한다.

## 미적용 후보와 검증

`candidates/`와 `verification/`의 파일은 제품에 적용됐다는 뜻이 아니다. 각 폴더의 상태·원본 핀·후보 핀·검토 범위를 먼저 읽는다. 기존보다 새로운 제품 파일을 후보 전체 파일로 덮어쓰지 않는다.

- 날짜축 V2: 원본 18개 실패, 후보 8개 실패로 거절했다.
- 날짜축 V3: 공개 합성 실제 primary의 월봉·주봉/최대·축소·재최대/처음·중간·최근 18개 상태에서 글자 경계 이탈과 겹침 0건. 독립 판정의 최소 인접 간격은 약 34.059px이다. 이는 실제 제공자 입력·네이티브 pan 또는 전체 94개 통과가 아니다. 원본 baseline은 과거 V2 결과 재사용이다. 날짜축 4파일은 아직 제품에 설치하지 않았다.
- 기업정보 축소 가격 이력 간격: CSS 후보는 미적용이다. 최초 측정기 실행은 exit 1이며 결과 파일이 없었다. 다음 관측기 실행 결과는 `verification/company/`에서 확인한다. 결과가 없거나 종료 상태가 불명확하면 통과로 집계하거나 같은 실행을 무조건 다시 시작하지 않는다.
- 시간 초과 카드: 큰 공백과 기본 스타일 버튼을 줄이는 CSS 및 버튼 클래스 후보는 미적용이다. 공개 실제 소비자 fixture는 준비됐지만 아직 실행하지 않았다.

## 재개 순서

1. Git 상태와 현재 소스 핀을 확인하고 이번 인계 이후 변경을 구분한다. 도구 handle·PID·창 ID는 다른 컴퓨터에서 재사용하지 않는다.
2. 전체 단위 검사 실패 46개와 취소 1개를 재현·분류한다. 실제 npm `test:unit` 결과는 tests 798 / pass 751 / fail 46 / cancelled 1 / skipped 0 / todo 0이다. 성공으로 표현하거나 skip으로 숨기지 않는다. 개별 공개 소비자 통과를 전체 suite 통과로 대신하지 않는다.
3. 미적용 후보와 별도 검토 보고서를 대조한다. 날짜축은 정확 4파일을 검토하고 적용 후 검사·실제 앱 검증을 수행한다. 오류 카드 및 기업정보 간격은 공개 렌더러 검증부터 완료한다.
4. 새 컴퓨터의 Computer Use 도구로 실제 앱을 실행하고 모든 94개 상태를 최대 2560×1392→같은 카드 축소 1411×1166→재최대화로 검증한다. 실제 달성한 크기를 기록하고, 하단·마지막 열·탭·정렬·펼침을 확인한다. 2122×1166 일반 창을 최대 창으로 계산하지 않는다.
5. 최소 입력 12개 seed와 추가 흐름 31개는 `backend/ref/card-ui-questionnaire.json`을 따른다. 카드 미도착은 UI NOT_RUN, 실제 템플릿 ID 미확인은 null이다. 일부 조작 통과를 전체 카드 통과로 합산하지 않는다.
6. 없는 금융 데이터를 채우지 않는다. API 계약이 다른 상단·하단 값은 복사·임의 합산하지 않는다. 실제 금융 화면은 ignored 로컬 증거로 보관하고 GitHub나 Paper에 올리지 않는다.
7. Paper 원본 101개 편집 도면을 보존하고 개선안은 별도로 작성한다. Paper 파일은 [ATHENA 앱](https://app.paper.design/file/01M3SB680J59QWZX6J4CGRVXT7/p-1-0)이며 호출마다 정확한 fileId를 사용한다. 새 컴퓨터에서 접근 권한과 현재 원본 개수를 다시 확인한다.
8. 변경에 맞는 검사, 독립 최종 검토, `powershell -File scripts/security/eval-security-gates.ps1`의 `ALL_GATES_PASS`를 확인한 뒤 UI 브랜치를 정상 push한다. main에 자동 병합하지 않는다.

## 증거 정정과 도구 상태

993·994 저장 이미지는 이전 화면을 참조해 현재 요청의 UI 근거에서 제외했다. 원본을 삭제해서 오류 이력을 숨기지 않는다. 995·996은 같은 실패한 차트 요청의 오류 화면 재관측이며 새 호출 두 건으로 세지 않는다. 기본 차트 UI는 NOT_RUN이다. 다른 컴퓨터에서는 캡처 관측을 저장 함수에 명시적으로 전달하고 현재 window 및 screenshotId로만 입력한다.

기존 컴퓨터의 Windows Computer Use helper는 창 목록 재시도와 JavaScript 세션 초기화 후에도 시간 초과했다. 이 사실은 새 컴퓨터의 도구 실패를 뜻하지 않는다. 새 환경에서 스킬의 초기화·복구 절차를 다시 따른다. 원래 컴퓨터의 창·프로세스·세션 handle을 재사용하지 않는다.

브라우저의 `file://` 질문지 미리보기는 해당 환경의 보안 정책으로 차단됐다. 이 차단을 다른 프로토콜, CDP 또는 대체 표면으로 우회하지 않는다. 질문지 내용 검토와 픽셀 검증을 구분한다.

LAYA 실험은 `codex/laya-experiments-20261001`에 분리되어 있으며 UI 재개 브랜치와 합치지 않는다. 전용 브랜치 `41c879121d061fa054c5e2fbb0d13625a56ed8c4`는 보안 검사와 정상 훅을 통과해 GitHub에 업로드했다. 다른 컴퓨터에서는 `git fetch origin` 후 원격 refs를 확인한다.
