# WTS 사이트맵 실시간 UI 발견 목록

조사일: 2026-10-19

대상: 로그인된 `https://wts.kiwoom.com/` 메인 화면의 사이트맵 modal

구조화 자료: [sitemap-inventory-20261019.json](sitemap-inventory-20261019.json)

이 목록은 실제 Chrome에서 사이트맵을 열고 modal의 `dt` 그룹과 바로 뒤 `dd` 안의 버튼 텍스트를 읽은 **발견 분모 스냅샷**이다. 확장 action, 실행 권한, 화면 전환 성공, 전체 W0 조사를 증명하지 않는다. WTS 애플리케이션 버전은 관찰한 UI에 노출되지 않아 날짜 기준으로 기록한다.

## 관찰 상태

- modal heading: `키움증권 웹트레이딩(WTS) 전체 메뉴`
- 초기 viewport: `498 × 677`
- 초기 modal 사각형: `x=630`, `y=90`, `w=622`, `h=492`
- 닫기 제어에 접근하기 위해 viewport를 일시적으로 `1800 × 1200`으로 바꿨다.
- 관찰 뒤 modal을 닫아 `isVisible=false`를 확인했고 viewport override를 초기 상태로 복원했다.
- 메뉴 버튼은 클릭하지 않았다. 계좌값·표 행·원시 HTML을 읽거나 저장하지 않았고 주문을 실행하지 않았다.

## 계산된 분모

| 항목 | 수 | 의미 |
|---|---:|---|
| `dt` 그룹 | 17 | 관찰 시점의 사이트맵 그룹 수 |
| 메뉴 버튼 | 50 | 닫기 버튼을 제외한 `dd` 내부 버튼 수 |
| 이름 있는 버튼 | 48 | 공백이 아닌 접근 가능한 텍스트를 가진 버튼 발생 수 |
| 고유한 이름 있는 버튼 | 44 | 그룹을 무시하고 같은 텍스트를 한 번만 센 수 |
| 이름 없는 버튼 | 2 | 뉴스 1개, 체결/거래 1개 |
| 하위 버튼이 없는 그룹 | 4 | 주문내역, 관심종목, 현금잔고, 차트 |

`매수`, `매도`, `정정/취소`, `종목별투자자`는 서로 다른 그룹에 같은 이름이 나타난다. 두 버튼은 이름이 비어 있다. 따라서 전역 텍스트 하나만으로 action 대상을 고를 수 없으며 그룹·영역·현재 상태·후조건을 함께 식별해야 한다.

## 해석 경계

관찰한 50개 메뉴 버튼의 DOM `disabled` 속성은 모두 `false`였다. 이 속성은 action 실행 권한, 계좌 권한, 안전성, 실제 화면 전환 성공을 뜻하지 않는다. 특히 주문·신용주문·주문내역·잔고·체결/거래는 **메뉴 이름을 발견한 것뿐**이며 계좌 데이터를 조회하거나 주문 동작을 시험하지 않았다.

하위 버튼이 없는 네 그룹의 `dt` 자체가 클릭 대상일 가능성은 있지만 클릭하거나 추론하지 않았다. 뉴스와 체결/거래의 이름 없는 버튼도 목적을 추정하지 않는다. 헤더에서 여는 시장종합·차트 같은 새 창과 화면별 context menu는 이 사이트맵 modal의 `dt → dd button` 분모 밖이므로 별도 발견 목록이 필요하다.

이 스냅샷의 17개 그룹·50개 버튼은 이전 [53개 진입 항목 조사](screen-inventory-20261018.json)와 같은 단위가 아니다. 이전 목록은 메뉴를 방문해 화면 구조를 기록한 조사이고, 이번 목록은 한 시점의 사이트맵 DOM 그룹과 버튼 발생 수다. 두 수를 합치거나 서로 대체하지 않는다. 화면 상태, 필터, 입력, 빈 결과, 오류, modal, 자식 창, iframe, canvas, 권한별 분기까지 조사해야 W0 분모를 고정할 수 있다.

## 다음 인수 증거

1. 같은 WTS release에서 사이트맵, 헤더 새 창, context menu, 검색 결과를 대조해 중복과 사이트맵 밖 진입점을 식별한다.
2. 각 발견 항목에 안정적인 화면 식별자, 필요한 계좌·상품·권한, 상태·입력·modal·자식 창을 연결한다.
3. 실제 확장 action은 등록된 대상만 한 번 실행하고 활성 상태·헤더·canvas·창 path 같은 사후조건과 receipt를 남긴다.
4. 주문·계좌 화면은 제품 범위를 유지한다. 실계좌 조회는 허용하지만 실계좌 주문·자동매매는 등록하지 않고, 모의 주문은 주문표마다 사용자가 개별 확인하는 계약이 구현된 뒤 검증한다.

공식 서비스 범위는 [키움 WTS 공식 설명서 기반 제어 맵](official-manual-control-map-20261018.md), 일반 브라우저에서 확인한 선택자·후조건은 [WTS 직접 브라우저 제어 검증](direct-control-validation-20261018.md), 확장 제품의 현재 증거는 [ATHENA → Chrome 이식 인수 대장](migration-acceptance-ledger-20261019.md)에서 구분해 관리한다.
