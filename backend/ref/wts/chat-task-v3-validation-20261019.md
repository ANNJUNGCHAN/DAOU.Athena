# WTS 대화 작업 v3 검증

검증일: 2026-10-19

대상: ATHENA WTS Chrome 확장과 사용자 PC 로컬 실행기 `0.3.0`, Native Messaging 프로토콜 3

## 현재 판정

소스, 격리 빌드, 설치 파일, 설치된 로컬 실행기의 stdio 계약까지 검증했다. 설치된 확장과 로컬 실행기 파일은 `0.3.0`으로 갱신됐지만, Chrome이 새 확장을 실제로 다시 읽었는지와 로그인된 WTS에서 복합 명령이 두 단계로 실행됐는지는 아직 확인하지 않았다.

따라서 현재 판정은 **0.3 설치 및 로컬 호스트 검증 완료, 실제 Chrome v3 대화 작업 검증 대기**다. 소스 테스트나 stdio 왕복을 실제 WTS 클릭 증거로 사용하지 않는다.

## 구현된 범위

프로토콜 3은 기존 화면 조사, 단일 제안, 영수증 형식을 유지하면서 제한된 영속 대화 작업을 추가한다.

- 로컬 결정형 한국어 해석기가 `차트 열고 주봉으로` 같은 완전히 해석 가능한 복합 문장을 단계로 나눈다.
- 한 작업은 최대 12단계다. 일부만 해석되는 문장, 잔여 텍스트, 부정 지시와 12단계를 넘는 입력은 실행 계획으로 승인하지 않는다.
- action catalog는 `wts.main.p3.chart.open`과 `wts.main.p3.chart.period.set` 두 종류뿐이다. 기간 인자는 `day`와 `week`만 지원한다.
- 각 단계 전에 새 화면 관찰을 요구하고, 브라우저가 한 번 실행한 뒤 후조건을 확인해 영수증을 기록한다.
- 작업 시작·조회·다음 단계·단계 commit·취소 상태를 로컬에 제한된 크기의 불변 파일로 보존한다.
- 생성형 계획기, LAYA, 로컬 생성 모델은 비활성이다. 런타임 capability도 `laya=false`, `localPlanner=false`, `generative=false`, `localModelReady=false`를 요구한다.
- 주문 action, 임의 selector, 임의 JavaScript·셸, HTTP 서버와 원격 provider는 포함하지 않는다.

이는 자유 형식의 ATHENA 대화나 전체 WTS 제어가 아니다. 현재 허용한 차트 명령을 순서대로 묶어 안전하게 실행하기 위한 좁은 파일럿이다.

## 검증 결과

### 소스와 계약

| 검증 | 결과 | 판정 범위 |
|---|---:|---|
| 공통 계약 | 13/13 통과 | 프로토콜 3 schema와 공통 validator |
| 로컬 실행기 | 65/65 통과 | 결정형 compiler, 영속 작업, CAS, 영수증, 복구와 실제 native-process fixture |
| Chrome 확장 | 104/104 통과 | 작업 coordinator, 단계 실행, panel 상태, 격리 build와 runtime gate |
| 합계 | 182/182 통과 | 실패·skip·todo 0 |

핵심 변경 31개 파일은 별도 검토에서 APPROVE를 받았고 남은 지적은 0건이었다. Chrome panel 변경도 별도 검토에서 APPROVE를 받았다.

동시 실행과 저장 경계는 다음 스트레스 검증을 추가로 통과했다.

- 독립 CAS 반복 20회
- 두 로컬 호스트가 같은 작업 revision을 경쟁하는 반복 10회
- receipt 저장 실패 뒤 같은 작업을 복구하는 반복 10회

각 검증은 하나의 durable winner만 남고, receipt가 저장되지 않은 단계가 공개 작업 상태를 전진시키지 않는 조건을 확인했다. 이는 테스트 환경의 동시성·복구 증거이며 실제 Chrome 탭의 실행 증거는 아니다.

별도의 로컬 계획기 Python probe는 11개 테스트와 Ruff 검사를 통과했다. 이 probe는 모델/runtime 적합성 조사를 위한 별도 경로이며 위 JavaScript 182개 합계나 0.3 제품 기능 완료 수에 포함하지 않는다.

### 격리 빌드와 설치

- 운영체제 임시 폴더의 격리된 stage에서 확장을 빌드하고 정적 검사를 통과했다.
- manifest key가 만드는 unpacked extension ID가 기존 설치와 동일하게 유지되는지 확인했다. 공개 문서에는 실제 ID를 기록하지 않는다.
- 계약, 확장, 로컬 실행기, 문서와 probe를 대상으로 한 민감정보 누출 검사가 통과했다.
- 설치 전 기존 `0.2.0` 코드 32개 파일을 사용자 로컬의 비공개 backup으로 보존하고 파일 해시 일치를 확인했다.
- 소유가 확인된 실행 중 native host 한 개를 정상 종료한 뒤 설치기를 실행했다.
- 설치된 로컬 실행기와 `extension/dist`는 `0.3.0`이며, 격리 stage의 20개 배포 파일과 설치 대상의 해시가 모두 일치했다.
- 설치된 실제 host에 stdio `runtime.hello`를 보내 `runtimeVersion=0.3.0`, `protocolVersion=3`, `taskMode=bounded-compound-v1`, 최대 12단계를 확인했다. 프로세스는 오류 출력 없이 정상 종료했다.

절대 설치 경로, 개인 확장 ID, 개인 데이터 파일명·해시와 backup 위치는 이 공개 검증 기록에 넣지 않는다.

### 기존 데이터 보존

업그레이드 전후의 사용자 로컬 데이터 10개 파일을 읽기 전용으로 비교했다. 기존 캡처 6건과 검증 영수증 4건의 해시는 모두 유지됐고 감사도 통과했다. 0.3 설치가 과거 증거를 새 v3 작업 증거로 바꾸지는 않는다.

## 남은 실제 Chrome 검증

문서 작성 시점에는 다음 항목이 확인되지 않았다.

1. Chrome이 새로고침 뒤 실제로 확장 `0.3.0`과 service worker를 로드했는지
2. ATHENA panel이 설치된 프로토콜 3 호스트에 연결되는지
3. `차트 열고 주봉으로`가 실제 WTS에서 차트 열기와 주봉 전환의 두 단계로 실행되는지
4. 각 단계가 새 관찰, 한 번의 클릭, 후조건과 서로 결합된 두 영수증으로 남는지
5. 실제 Chrome에서 취소·연결 상실·재시작·receipt 저장 실패가 안전하게 복구되는지

두 단계 정상 경로를 분명히 보기 위해 WTS P3는 일봉 상태를 확인한 뒤 종목시세로 이동해 두었다. 이 준비 상태 자체는 v3 성공 증거가 아니며 사용자가 다른 화면을 조작하면 달라질 수 있다.

실제 확인 순서는 다음과 같다.

1. `chrome://extensions`에서 ATHENA 확장을 새로고침한다.
2. WTS에서 ATHENA panel을 다시 열고 표시 버전 `0.3.0`과 로컬 실행기 연결을 확인한다.
3. `차트 열고 주봉으로`를 한 번 전송한다.
4. Chrome UI의 단계 진행과 최종 상태를 확인하고, 로컬 저장소에서 새 작업·관찰·영수증의 결합을 읽기 전용으로 감사한다.

이 확인 전에는 “Chrome 대화 작업 v3 완료” 또는 “실제 2단계 제어 완료”라고 표시하지 않는다.

## 전체 이식과 로컬 모델 경계

현재 ATHENA 23개 기능 중 완료된 기능은 0개다. 화면 호출의 좁은 차트 기능만 부분 상태이며, 0.3 설치가 다른 기능을 자동으로 완료시키지 않는다. [ATHENA → Chrome 이식 인수 대장](migration-acceptance-ledger-20261019.md)의 전역 게이트와 기능별 실제 Chrome 흐름이 계속 필요하다.

M-1 로컬 계획기 적합성도 통과하지 않았다. CPU probe와 설치 환경 조사는 후보 실행 가능성 자료일 뿐 모델 선정·성능·재배포 적합성 증거가 아니다. GPU 실측에 필요한 추가 runtime 설치 여부도 아직 결정되지 않았다. 로컬 생성 모델이 검증될 때까지 결정형 명령 범위를 생성형 대화나 LAYA 완료로 확대하지 않는다.

이전 실제 Chrome의 단일 명령 근거는 [차트 파일럿 검증 기록](chart-pilot-validation-20261018.md), 전체 이식 판정은 [인수 대장](migration-acceptance-ledger-20261019.md)에서 구분한다.
