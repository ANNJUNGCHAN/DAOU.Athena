# 자연어 전략과 LAYA 모의 감시

2026-10-01 구현·검증 기록. 실매매와 실제 주문은 범위에 포함하지 않는다.

## 사용자 흐름

Athena를 최신 소스로 다시 시작한 뒤 **팔라스 → 자연어 전략 · LAYA 모의 감시**를 연다.

1. 진입·청산·그 외 행동을 자연어로 적고 **LAYA 판단 설계**를 누른다. 현재 선택한 Codex 또는 Claude 모델이 제한된 JSON 판단 스키마를 작성한다. Python 전략 파일을 작성하거나 생성하지 않는다.
2. 모델이 정리한 한국어 해석, 진입·청산 질문, 후보 행동, 필요한 관측값을 확인한다. 애매하거나 지원하지 않는 조건이면 확인 질문을 반환한다. 원문을 바꾸면 다시 설계해야 한다. 백엔드가 형식·관측값·길이를 검증하고 원문과 작성 모델, 스키마 버전·해시를 붙인다.
3. 합성 예제 또는 이미 저장된 한 종목의 수정주가 일봉을 고른다. 캐시 조회는 종목코드와 시작·종료일을 받는다. 이 기능에서 외부 데이터 수집은 하지 않는다. 초기 자금, 양방향 수수료, 매도 세금, 슬리피지를 확인한다. 화면의 초기 값은 편집 가능한 가정이며 적용 세율을 주장하지 않는다.
4. **검토한 조건으로 모의 시작**을 눌러 확인한 스키마를 세션에 고정한 뒤 **다음 봉** 또는 **남은 봉 연속 실행**을 누른다. 그 후 시점별 선택은 LAYA가 실제 수행한다. **일시 정지**는 처리 중인 판단 한 건이 끝난 뒤 멈춘다.
5. 차트에서 종가 판단, 모의 매수·매도 체결, 보유 수량, 평가자산을 확인한다. 봉 선택기로 현금·체결가격·수수료·세금·실현손익을 확인하고, 원문 요청/응답과 전체 기록을 JSON으로 내보낸다.

감시는 선택한 과거 데이터의 순차 재생이다. 실시간 시장을 계속 조회하는 서비스나 실제 주문 실행이 아니다. 세션은 백엔드 메모리에 있으며 재시작하면 사라진다. 최대 512봉, 8개 세션을 지원한다. 새로 모의 시작하면 현재 보고 있는 일시 정지·완료 세션을 교체하므로 보관할 기록은 먼저 내보낸다. 잘못된 새 입력이나 진행 중인 세션의 교체 요청은 기존 세션을 보존하고 거부한다.

## 판단과 체결의 경계

상위 모델은 사용자의 기법을 LAYA 질문으로 작성하고, 사용자가 그 해석을 확인한다. 실행 때는 현재 봉까지의 실제 관측값을 해당 질문에 넣고 LAYA가 행동을 선택한다. 상위 모델이나 템플릿 렌더러가 각 봉의 정답을 대신 계산하지 않는다. 질문에 포함된 수치 비교·AND/OR/부정 조건도 LAYA가 판단한다.

기존 `engine.run_backtest`에 종가 판단 콜백만 추가했다. 당일 대기 주문 체결과 기존 리스크 처리가 끝난 실제 계좌 상태를 받아 LAYA에 전달한다.

- 무보유: `enter` / `wait`만 허용한다.
- 보유: `exit` / `hold`만 허용한다.
- 현재 종가의 판단은 다음 체결 가능 봉 시가에 반영한다. 마지막 봉의 새 신호는 체결되지 않는다.
- 거래량 0 또는 OHLC가 모두 같은 봉에서는 대기 주문이 다음 봉으로 이어진다. `wait`/`hold` 및 서버 장애가 기존 대기 주문을 취소하지 않는다.
- 체결·수량·수수료·세금·슬리피지·현금·평가손익은 기존 엔진이 계산한다. 전액 단일 포지션, 소수 수량, 마지막 봉 미청산 유지도 기존 가정이다.
- 화면의 자연어 경로는 별도 강제 손절·익절을 사용하지 않는다. 자연어 청산은 다음 봉 시가의 신호 청산이다. 파이썬 모듈에 명시적 리스크를 제공하면 기존 엔진의 봉 내부 리스크 규칙을 재사용한다.

현재까지의 봉만 provider에 복사해 전달하며, 미래 구간을 바꿔도 앞선 판단 요청이 바뀌지 않는 것을 테스트했다. 수정주가 캐시 자체가 과거 시점에 알려진 그대로의 데이터인지, 사용자가 적은 조건에 미래 지식이 포함됐는지는 이 검증이 보증하지 않는다.

## 모델 입력과 실패 처리

LAYA는 자유 생성 모델이 아니다. `/v1/systemone`의 `choice` 질문 하나와 행동 후보 두 개를 사용한다. 선택지는 주어진 행동으로 고정하고, 종목·날짜·전략 코드를 모델이 만들어 내게 하지 않는다.

로컬 서버 기본 주소는 `http://127.0.0.1:8768`이며, 어댑터는 로컬 HTTP 주소만 허용한다. 환경 프록시와 리다이렉트를 사용하지 않는다. 공통 LAYA 라우팅 설정·클라이언트와는 별도 모듈이다.

새 스키마 경로의 모델 입력은 다음과 같다.

- 사용자가 확인한 `flat` 또는 `holding` 질문 하나와 후보 두 개. 질문의 `{close}`, `{sma_5}` 같은 참조에는 코드가 현재·과거 자료로 계산한 정확한 JSON 숫자 표현을 넣는다. 문자열 치환만 하며 Python이나 수식 코드를 생성·실행하지 않는다.
- 판단 시점, 보유 여부, 관측 봉 수와 현재 질문에서 참조하는 숫자 관측값. 지원 값은 현재 `open/high/low/close/volume`, `previous_close`, `sma_5`, `sma_20`, `volume_ma_5`, `cash`, `qty`, `entry_price`, `unrealized_return_pct`이다. 미실현 수익률은 `(현재 종가 / 실제 모의 진입가격 - 1) × 100`이며 거래비용을 차감한 수익률이 아니다.
- 필요한 과거 봉이 부족하거나 보유하지 않아 진입가격을 알 수 없으면 모델을 호출하지 않고 `missing_observation` 사유로 관망/보유한다. 현재 질문만 검사하므로 청산 질문의 20일 평균 때문에 무보유 진입 질문이 막히지 않는다.

스키마는 `schema_version`, `source_text`, `title`, `explanation`, `required_observations`, `flat`, `holding`, `author`, `schema_hash`를 가진다. 모델 초안에는 해석과 질문만 허용하고 출처·버전·해시는 애플리케이션이 붙인다. 관측값 자체, 알 수 없는 필드·관측값, 후보 밖 행동은 스키마로 허용하지 않는다. 스키마를 수정하거나 다른 원문에 재사용하면 검증에 실패한다. 단, 해시는 전자서명이 아니며 모델의 해석이 원래 의도를 완전히 보존했다는 의미도 아니다. 실행 전 해석 검토가 필요한 이유다.

질문은 320 UTF-8 바이트, 각 후보는 이름·구분자 포함 44바이트, 전체 질문 헤드는 보수적으로 480바이트 이내로 제한한다. 치환 후에도 다시 검사한다. 서버에는 `max_len=2048`, `head_max_len=512`를 지정하며 긴 조건을 조용히 자르지 않는다. 원문이 길더라도 확인한 실행 스키마가 예산에 들어가면 사용할 수 있다.

이전 직접 자연어 경로는 기존 평가와 재생 호환을 위해 Python 모듈에 남아 있다. 이 경로는 원문·계좌·파생 지표·최근 최대 20봉을 예산 안에서 전송한다. 앱의 새 설계·확인 흐름은 준비된 스키마를 사용한다.

뉴스, 재무, 시장 전체 상태나 임의 지표는 제공하지 않는다. 상위 모델은 지원하지 않는 조건을 조용히 다른 조건으로 바꾸지 말고 확인 질문으로 반환하도록 지시받는다. 구조 검증과 사용자 확인이 있어도 자연어 해석의 정확성이나 LAYA의 조건 준수가 보장되는 것은 아니다.

미학습 `noul`·잘못된 응답·법적 후보 밖의 선택·서버 장애·불확실 응답은 새 행동을 관망/보유로 바꾼다. 답 확률 0.65와 후보 간 차이 0.10은 평가 전에 정한 대체 정책이며 정확도를 보증하는 신뢰도 기준이 아니다. 높은 점수로 틀릴 수도 있다.

## 실제 상위 모델 → 스키마 → LAYA → 체결 평가

2026-10-01 현재 연결된 Codex `gpt-5.6-sol`, 추론 `low`가 실제로 자연어를 읽어 스키마를 작성했다. 검증용 초안이나 판단 응답을 손으로 대체하지 않았다. 작성된 한국어 해석에서 전일 종가의 엄격한 대소 비교, 5일 평균·거래량의 AND, 청산의 OR와 3% 경계를 확인했다. `현금 50% + RSI(14)` 요청은 지원하지 않는 조건을 누락하지 않고 확인 질문을 반환했다. 이 한 사례로 모든 미지원 전략을 감지한다고 일반화하지 않는다.

작성 프로세스는 앱에 연결된 계정을 사용하며 별도 임시 작업 디렉터리, 도구 비활성화, 세션 재사용 금지를 적용한다. Codex는 읽기 전용 환경과 구조화 출력, Claude는 빈 MCP 설정과 `--strict-mcp-config`를 사용한다. 원문이 애매하거나 관측값이 지원되지 않으면 사용자가 조건을 고쳐 다시 설계한다. 백엔드의 형식 오류는 같은 상위 모델에 최대 한 번 수정 요청한다.

처음에는 후보를 `Enter`/`Wait` 같은 행동 이름으로만 작성하도록 했고, 세 가지 연속 실험 모두 LAYA가 36봉 내내 관망했다. 설치된 LAYA 0.3.21 SDK의 후보 토큰 구성과 공식 분류 예제를 확인한 뒤, 후보가 **그 행동이 맞는 조건의 의미**를 나타내도록 작성 지침을 고쳤다. 가격 비교 정답을 코드가 대신 계산하거나 모델 선택을 덮어쓰지 않았다. 아래는 이 변경 후 고정한 두 번째 작성 지침의 결과다. 초기 실패 기록도 `compiled-*.json`에 남겼으며 후속 결과는 `compiled-*-v2.json`으로 구별한다.

각 전략은 같은 36봉 합성 OHLC를 순차 실행했다. LAYA 모델과 revision은 아래 직접 자연어 실험과 같고 실제 응답의 장치는 `cuda`였다. 원래 선택의 정답 분모는 모델을 호출한 봉 수이며, 적용 행동의 분모에는 지표 준비 기간의 관망도 포함한다.

| --- | ---: | ---: | ---: | ---: | ---: |
| 전일보다 상승하면 진입, 하락하면 청산 | 35 | 21 / 35 | 23 / 36 | 매수 1건 | 1 / 25 |
| 종가 > 5일 평균 AND 거래량 ≥ 1500 진입, 종가 < 5일 평균 OR 미실현 수익률 ≥ 3% 청산 | 32 | 18 / 32 | 12 / 36 | 매수·매도·매수 3건 | 4 / 29 |
| 미보유면 무조건 진입, 보유면 무조건 청산하는 연결 점검용 대조 전략 | 36 | 1 / 36 | 1 / 36 | 매수 1건 | 0 / 35 |

복합 전략에서는 초기 모의 자금 1,000,000원, 수수료 10bps, 매도 세금 20bps, 슬리피지 5bps로 세 체결을 기록했다. 수수료 합계 2,934.64원, 세금 1,939.51원, 마지막 평가자산 1,048,305.72원이다. 실제 시장 자료나 수익성 근거가 아니다. 이 전략의 틀린 적극적 행동은 2회였으며 대조 전략은 요구한 반복 청산을 수행하지 못했다. 연결 및 회계 작동은 확인됐지만 **현재 LAYA의 조건 준수 정확도는 신뢰할 수준에 도달하지 못했다.**

스키마와 정책을 고정한 뒤 다른 합성 상태로 등호·상하 경계, 거래량 1499/1500/1501, 보유 중 3% 경계를 검사했다. 새로운 상태 20개에 후보 순서 2종을 적용한 40회에서 원래 선택과 적용 행동 모두 17/40 정답, 틀린 진입·청산 12회, 확률 하한 대체 23회였다. 순서 교체에 따른 원래 선택 불일치는 5/20쌍이었다. 별도의 동일 입력 반복·순서 진단 24회에서는 반복 불일치 0/12쌍, 순서 불일치 0/12쌍이었다. 모델의 선택은 입력과 후보 표현에 민감하며 이 결과로 임계값을 다시 조정하지 않았다.

세 연속 실행 모두 API 응답을 Node의 `JSON.parse`/`JSON.stringify`로 내보낸 뒤 Python에서 모델 없이 재생하여 체결·비용·평가자산이 정확히 일치했다. 이 과정에서 정수 값의 `1.0 → 1` 변환으로 개발 중 기록의 해시가 어긋나는 문제를 발견해 `hash_version: 2`에서 숫자 표현을 정규화했다. 다른 숫자·행동·조건의 변경은 계속 거부한다. 이전 형식의 직접 Python 기록은 버전 1 해시로 검증한다.

전체 결과는 `artifacts/natural-backtest/compiled-evaluation.json`, 원문·스키마·요청·응답·체결은 `compiled-up-down-v2.json`, `compiled-compound-v2.json`, `compiled-positive-control-v2.json`, 미지원 조건 응답은 `compiled-unsupported-v2.json`에 있다. `author_probe.cjs`는 실제 상위 모델 작성과 API 연속 실행, `compiled_evaluate.py`는 오프라인 재생·정답 비교·후보 순서·새 경계 사례를 재현한다. 이들은 로컬 검증 산출물이며 공개 저장소에 포함하지 않는다.

## 실제 로컬 LAYA 평가: 직접 자연어 기준 실험

모델 `convaiinnovations/laya-multilingual`, revision `e4e9ddf21a7b1903b7acffd8814ad4307bf63a67`, LAYA `0.3.21`, 실제 CUDA 장치 RTX 3060에서 실행했다.

아래 수치는 상위 모델 스키마 작성 단계를 추가하기 전, 직접 자연어 입력 경로의 기준 실험이다. 새 스키마 경로의 정확도로 인용하면 안 된다. 한국어·영어 AND/OR/부정/경계값/보유 중 청산을 포함한 합성 조건 34개를 만들었다. 후보 순서 2종과 반복 2회로 총 136개 요청을 보냈다. 정답은 평가기에만 있고 모델 요청에는 포함하지 않았다.

| 평가 항목 | 결과 |
| --- | ---: |
| 원래 모델 선택의 조건 정답 | 54 / 136 (39.7%) |
| 관망·보유 대체를 적용한 실제 행동의 조건 정답 | 50 / 136 (36.8%) |
| 항상 관망·보유하는 기준 정답률 | 52.9% |

| 틀린 진입·청산 | 66회 |
| 후보 순서 교체 시 원래 선택 불일치 | 10 / 68쌍 |
| 같은 요청 반복 시 원래 선택 불일치 | 0 / 68쌍 |

**이 실험은 현재 체크포인트가 복합 조건을 신뢰성 있게 수행한다는 기준을 통과하지 못했다.** 규칙 기반 전략을 대체할 준비가 됐다고 판단하지 않는다. 수익 예측·수익률 검증도 아니다. 모의 감시 화면은 이 실패와 판단 원문을 관찰할 수 있는 실험 기능이다. 평가 결과를 보고 이 데이터에 맞춰 임계값을 다시 조정하지 않았다.

전체 평가 기록: 저장소의 `artifacts/natural-backtest/laya-condition-evaluation.json`. 로컬 산출물로 보존하며 공개 저장소에 포함하지 않는다.

별도의 36봉 합성 연속 실행에서는 실제 LAYA의 판단을 기존 엔진으로 체결했다. 모의 체결 21건, 수수료 합계 32,230.69원, 매도 세금 184,579.27원이 기록됐고 모델 없이 재생한 체결·평가자산이 정확히 일치했다. 이 조건의 적용 행동 정답은 24/36이고 확률 하한에 따른 관망·보유 대체가 15회 있었다. 이 결과도 합성 입력 한 사례이며 수익 성과나 일반적인 정확도의 근거가 아니다. 기록은 `artifacts/natural-backtest/laya-sequential-simulation.json`, 재현 스크립트는 같은 폴더의 `run_simulation.py`이다.

## 재현과 구현 위치

기존 로컬 서버가 실행된 상태에서 저장소 `backend` 디렉터리에서 실행한다. 새 런타임 설치나 서비스 배포는 필요 없다.

```powershell
.venv\Scripts\python.exe -m athena_api.backtest.natural_evaluate --output ..\artifacts\natural-backtest\laya-condition-evaluation.json
.venv\Scripts\python.exe -m pytest verification\test_natural_backtest.py verification\test_natural_laya.py verification\test_natural_schema.py verification\test_natural_api.py -q
```

`NaturalSimulation`은 현재 봉까지의 기존 행동을 동일 엔진으로 재생한 뒤 새 봉에서만 모델을 한 번 호출한다. 구현 중복을 줄이기 위해 최대 512봉의 O(n²) 재생을 선택했다. 대규모 장기 실행을 위한 증분 엔진으로 일반화하지 않았다.

내보낸 JSON에는 입력 데이터·비용·리스크, 원문 모델 요청/응답과 모델 revision, 적용 행동·대체 사유, 요청/결정/입력 해시, 체결과 평가자산이 들어간다. `athena_api.backtest.natural.replay_natural(report)`는 서버 호출 없이 기록된 행동을 재생하고 관측 상태 및 회계 결과를 비교한다. 해시는 실수로 인한 변경 탐지용이며 신원·진위를 증명하는 서명은 아니다.

주요 파일:

- `athena_api/backtest/natural.py`: 순차 모의 실행, 시점별 감사 기록, 오프라인 재생.
- `athena_api/backtest/natural_laya.py`: 제한된 로컬 choice 어댑터와 실패 정책.
- `athena_api/backtest/natural_schema.py`: 스키마 계약·관측값·후보 검증과 원문 바인딩.
- `athena_api/backtest/natural_evaluate.py`: 실제 서버의 조건 준수 평가 CLI.
- `athena_api/api/backtest_natural.py`: 작성 계약·스키마 검증·세션 생성·진행·일시정지·결과 조회.
- `app/lib/main/natural-strategy-author.js`: 현재 선택한 실제 상위 모델 호출과 제한된 수정 재시도.
- `app/lib/backtest-natural.js`: 자연어 입력과 모의 감시 화면.
- `app/lib/backtest-natural-chart.js`: 처리된 봉만 표시하는 가격·판단·체결·평가자산 차트.

자연어 API는 배포/자동주문 모듈을 호출하지 않는다. 기존 코드 전략 경로는 유지하며, 다른 채팅에서 작업 중인 일반 대화·카드·MCP용 LAYA 연동과 별도 파일로 구현했다.
